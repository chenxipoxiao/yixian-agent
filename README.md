## 八人整局流程验证

已接入 `sharpobject/yxp_replays` 的少量真实数据，当前默认流程可直接运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m yixian flow
```

它从 8 个来源局中选 7 条人类玩家轨迹作为对手，另一个来源局提供自身初始牌组及百家之道候选。每轮只读对手当轮或更早的快照，单独维护本次模拟的命元，依次完成副职选择、升本、普通仙命、赛季选择、摆牌、存活者配对、结算及淘汰。换一个 `--seed` 可改变抽样与测试配对。策略仅接收自身状态和当前合法候选，不能读取对手私有手牌、未来快照或回放原选择。

本次默认流程完成8人、18轮、59场测试对战，产物为 `runs/flow/20261111T083137Z-30a23282/`。最新运行指针为 `runs/flow/latest.json`。历史17轮、58场测试对战以及早期无效果运行 `runs/flow/20261111T070457Z-4c4bbb97/` 原样保留；规则更新后不能把旧报告当作当前版本验证。

**默认流程仍用可重复的测试战果推进，禁止用于策略训练或实力评估。** 已有独立卡池与轮次规则组件，但完整合法卡池、实际换牌/合成/炼化操作和从发牌到淘汰的真实战斗尚未全部接入。`round_draw_provider` 通过 `pool_draw.py` 接收明确声明的卡池，不由整张卡表猜测合法池；两轮实际抽出6张且库存相应减少、满手后的抽牌转修为已通过独立测试，这不代表完整合法池已补齐。摆牌仍是脚本测试策略，尚未把历史PPO权重接到原始游戏卡牌ID。记录型对手不会根据新历史重新决策；缺轮沿用过去快照会记入日志。

换牌账户只用回放初始化一次。修为通常仍导入逐轮回放，只有被本次模拟中反事实仙命效果改变后才切换为独立增长账户；所有导入调整、基础增长、转换和奖励均记账。`original_actions_reconstructed=false`，不得把余额可对账写成完整操作已复原。


目前采用的规则与边界：

- 基础境界生命 `[40,45,52,62,75,100]`、修为门槛 `[0,9,21,36,55,75]` 来自本地配置。突破是否消耗修为及特殊减免另待核对。
- 用户提供的4张游戏官方FAQ截图及后续明确确认保存于 `data/inspection/user-faq-2026-11-11.json`；它是规则说明证据，不是服务器代码审计。
- 每轮基础 `+2修为、+2生命上限`，抽2张门派牌和1张副职牌；第12轮起再从门派、副职的**剩余实体合并池**抽1张，不能先按50/50选类别。仅轮初自动抽牌：每超出12张1张，就从本轮抽牌序列末尾少抽1张并加1修，最多转换本轮应抽量；保留顺序为两门派、一副职、轮次奖励合并池。仙命抽牌和换牌不受此限制。
- 本赛季换牌机会：第1–9轮每轮+3，第10–12轮+4，第13轮起+6；默认储存上限25。该表已替换旧社区重建器参考表。
- 独立牌库按每名玩家、每局重置；炼气至元婴每种8张、化神6张，洗髓丹/锻体玄丹/悟道丹各3张。抽牌扣池，获得复制和炼化不扣池；空合法池返回走火入魔。
- 普通换牌排除同名牌，练笔例外；本赛季额外删门派3张、副职2张同名牌。含置换效果通常免额外删除，五行璞玉例外。筑基/金丹/元婴每轮首次换牌：首次结果不同境界则归还原池后仅重抽一次，接受第二次结果；两次都遵守同名排除。合法卡池与特殊效果需另外显式提供。
- 命元扣除使用客户端静态恢复的普通分支及当前已接入修正。历史1,004条记录基础分支匹配966条，不代表特殊分支全部通过。双方最终HP都严格小于0时较大者获胜，相等则先手胜；尚未确认的0/0边界保留未解决，截断或待复活不能提前判胜。
- 同轮淘汰排序、单数存活者轮空和随机配对都是明确标记的测试约定，不能当作当前排位规则。

百家之道的出现轮次与修士可直接从 `xianMoData.npcDisplayDatas` 读取，再以本地 NPC 配置映射名字。候选和选择在 `strategies` 中，其 `id` 是出现轮次，**不是 NPC ID**。例如本次流程取到第 1 轮公输钥、第 3 轮九节、第 10 轮白衣老者；每局会不同。首跳过可能把对应轮的显示修士改成狻猊，必须结合 `suanNiSelectionData` 与个人历史解释。报告会记录来源与名字，不自行猜测安排。

模块分工为：`replays.py`保留证据及时间边界；`replay_pool.py`构建按轮对手轨迹；`match_flow.py`推进阶段和持久账户；`card_pool.py`处理显式独立牌库；`round_rules.py`生成轮次资源计划；`season.py`校验候选；`effects.py`及相关模块执行已支持组件；`settlement.py`实现基础扣血；`flow_demo.py`连接流程。测试战果始终与可训练样本分开。

## 原始回放采样

已固定数据集提交 `b592caa9bc6c3b9fb11bb8b3e7691b9840dd36ce`，只下载一个 **10,668,473 字节**的分片并核对官方 SHA-256。抽取 8 个完整来源局、64 份视角记录、1,004 条回合快照；源版本为 `001.0008.0005`，与本地资源目录版本分别保存。未下载全库。

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/import_replays.py --games 8 --archive 34499000.tar.zst --revision b592caa9bc6c3b9fb11bb8b3e7691b9840dd36ce --out runs/replays/another-sample
```

该命令使用 Python 3.14 内置 Zstandard，缓存分片时校验哈希；设有下载、解压、单文件及成员数量上限。不会按照 tar 路径直接解压。已经存在的导入报告不会被覆盖，重复导入请指定新的 `--out`。

样本为方便检查的小规模抽样，不代表真实玩家分布。`gameId` 用于同局多视角分组；`record-player-N` 限定在单份记录内，不推断跨视角相同身份。顶层 `uid` 可能与实际逐轮参与者不一致，导入时不会据此套用整局名次或评分。数据中 `life` 是命元，不是战斗 HP；`lastRoundData`、当前公开快照和私有快照分开保存。回放包含赛季候选与累计选择记录，**不是每次抽牌、换牌和移动操作的完整轨迹**。

## 历史排牌实验

实验目录：`runs/20261111T063152Z-401316e3/`。85 项软件测试通过；24 轮更新，共 576 场有效训练，没有截断标签进入训练。72 个合成局面来源分为训练 42 个、验证 18 个、测试 12 个；每个评测集运行 96 个种子。

这是当时冻结契约下的历史结果。之后桥接、原生赛季组件及规则发生变化，旧权重需重新通过契约校验和评测，不能直接宣称适用于当前环境；85项是该次实验的测试数，不是当前测试总数。

| 评测 | PPO 模型 | 随机选择下一张 | 保留输入槽位顺序 |
| --- | ---: | ---: | ---: |
| 验证集 | 39.6% | 37.5% | 47.9% |
| 保留测试集 | 57.3% | 52.1% | 63.5% |

表格为参考引擎内的合成对战胜率。两种基线的输入都经过固定种子打散；“保留输入槽位顺序”直接按打散后的顺序出牌。多种子重复使用同一来源局面，不是 96 场独立真实比赛。**模型没有超过全部基线，本轮只证明流程能运行，未通过策略提升条件。** 完整对局晋级还因规则未校准、完整环境缺失和无真实回放验证而被阻挡。

排牌命令形式如下；历史模型在当前契约不一致时会被拒绝，不能跳过校验：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m yixian arrange runs/20261111T063152Z-401316e3 examples/battle.json --out runs/arrangement-demo.json
```

`arrange` 会核对模型与当前代码、引擎及数据契约；版本不一致时拒绝加载。换模型时将目录替换成 `runs/latest.json` 中的 `run_dir`。它输出离线牌序及参考战斗结果，不控制游戏客户端。

续训接口为 `yixian.learning.train(env, config, contract, checkpoint_path, resume=True)`：除追加更新次数外，超参数须保持一致；保存优化器、随机状态和已用种子，避免假续训。独立测试集不可用于挑选超参数；若后续研究用它诊断和选择，须另设未使用的保留集。

## 按论文流程推进

1. **固定版本和规则证据**：本地卡表、角色、仙命、境界及赛季配置分别留档；先核对当前卡池，再移植卡牌效果。
2. **战斗校准**：从真实回放抽局面，比较每次行动、生命/护甲/灵气/状态及结算。随机事件需记录结果或采用分布验证；未知随机种子不能冒充逐步精确复现。
3. **完整局环境**：补发牌、换牌、合成、炼化、突破、仙命和赛季选择、配对、命元损失、淘汰与名次。配置或证据不足的规则必须登记，不能用猜测默认值伪装已实现。
4. **建立可比较基线**：先固定脚本策略和受限搜索；用真实回放校准各轮对手状态分布。之后训练小模型，先做本机小实验，再根据吞吐量决定算力。
5. **训练与独立评测**：模仿学习需要操作证据，回合快照不能直接当完整操作轨迹。PPO 需完整合法动作和终局回报。训练、验证、测试必须按整局 `game_id` 切分，同局所有玩家视角一起归属。
6. **实战反馈闭环**：每次差异归因到规则、输入编码、对手库或策略，修复后重新评测。单个固定牌局赢了不代表整体变强。

策略仅接收玩家当时可见的信息；对手隐藏手牌、未发生的抽牌和未来对局信息只存在于环境侧，不能泄漏给策略或搜索。

`yixian/research.py` 的 `contract_digest`、`check_replays`、`promotion_gate` 实现基础验证。真实来源标记只是溯源信息，不是对记录真实性的自动认证。模板 `examples/replay-template.jsonl` 明确是模拟自检，不能计入真实游戏证据。
