## 接手顺序

1. 先读[阶段计划](TRAINING_STAGES.md)和[战术模型说明](TACTICAL_AGENT_V3.md)。最新快照的入口是 `yixian.full_battle_v204.compile_start` 和 `tools/full_battle_bridge_web_v196.mjs`。README 与 AGENTS 中按日期保留了早期进展，历史样本数应连同当时的版本一起使用。
2. 仓库中的[实验记录](../runs/stages/)保留了牌序验收、扩样评估及换牌评估的选定文件。原工作机的 `runs/stages/latest.json` 指向最新阶段，`runs/pretraining/latest.json` 追踪权重，`runs/research.sqlite` 保存研究事件。历史记录里的绝对路径以原工作机为准。
3. 在仓库根目录运行下列轻量检查。CPU 训练依赖见 `requirements-training.txt`，T4 环境见[云端说明](CLOUD_SETUP.md)。完整战斗复测还需要对应版本的外部引擎、规则检查资料及回放。
4. 接续经营训练时，优先验证何时继续换牌、何时停止，以及抽牌、炼化、突破后资源与合法操作能否逐轮衔接。八人状态能独立推进后再评估整局策略。评测按整局隔离，固定同局面、同种子和引擎，分别报告胜负、命元差、淘汰与最终名次。

```powershell
python -m unittest discover -s tests -p test_round_rules.py
```

## 资料和运行环境

源码在 `yixian/`，规则核对、训练和诊断入口在 `tools/`，配置在 `configs/`，测试在 `tests/`。部分阶段专用程序与报告保存在原工作机的 `runs/stages/`。仓库提供代码及精选实验记录，复现完整实验还需从原工作机恢复 `data/inspection/`、相应 `external/`、数据划分、实验目录与权重；核对冻结清单和哈希后使用。原始回放、客户端、个人状态、云主机地址、完整模型和研究数据库留在原环境。

云端 SSH 别名为 `yixian-gpu`，项目目录为 `/home/ubuntu/yixian-agent`。新环境可复制 `configs/cloud_training.example.json` 为本机专用的 `configs/cloud_training.json` 并配置 SSH。复核历史文件哈希时应恢复原始配置。首次接管在恢复环境后运行 `python tools/monitor_training.py --ssh` 核对已有作业。S1 推理导出与含优化器的云端检查点用途不同，当前训练器没有精确续训接口。
