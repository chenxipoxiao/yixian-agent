# 通用摆牌与分层经营：v3 第一阶段

2026-11-12 按用户新方向实施。当前完成的是可继承旧模型的数值特征候选生成器、有限信息接口、受限数值搜索和验证工具。经营策略、对手概率模型、当前版本完整战斗与八人整局环境尚未完成。不能把以下接口或软件场景当作完整自我博弈训练。

## 决策分工

- 通用摆牌：输入明确可用的牌组、角色战斗状态和对手假设，由战斗引擎计算候选顺序；角色、仙命、刻印差异在引擎规则中执行。神经网络仅提高候选质量，不能用牌序复现分数替代战斗数值。
- 经营与路线：百家、副职、道韵、突破、换牌、留牌和抢先手必须联合考虑当前战力、成型概率与强度、过渡命元损失、资源/转型成本和对策功能。保留多条可调整路线。`TacticalCatalogue.describe_route` 已让过渡、目标和对策牌共享当前数值输入，但这些维度的估值器尚未训练；目标卡组不是已经能抽到的事实。
- 对手不确定性：每名 AI 只收到自己的私有准备状态及其他席位已经公开的历史。不能从修为唯一确定未知手牌；需要资源与随机事件条件下的候选分布。当前接口接收明确声明的假设概率，尚无经过校准的概率预测器。

## 已实现的接口

`yixian/tactical_rules.py` 固定数值字段、8个有序效果参数槽和逐字段已知掩码。缺失与0不同。参数没有被误命名为通用伤害。配置、字段语义与规则版本一起计算指纹；这些元数据不是合法卡池或执行覆盖认证。

`yixian/tactical_model.py` 在 S1 网络上增加数值残差，当前5,597,441参数。初始残差为0，按稳定卡牌ID迁移旧权重，初始化输出保持S1行为；训练会更新残差和网络。没有恢复旧优化器/随机流，因此是热启动，不是精确续训。新网络结构通用，但本次数据仍仅真人龙瑶记录牌阵，未证明跨角色有效。

`yixian/tactical_checkpoint.py` 独立加载v3，校验权重、源码、词表、数值指纹。新版本配置必须明确选择重新评测模式；会替换旧检查点中的数值缓冲区，不能默默继续使用旧数值。新增卡牌ID需要显式扩词表、迁移已有ID权重及重新评测；新的机制仍需更新战斗执行器。`generate_proposals` 使用自身前缀生成合法候选，不读真人正确前缀。

`yixian/tactical_information.py` 仅接受环境生成的显式可见性数据，不能直接输入回放的`publicData`，因为其中可能有手牌。八席决策先冻结各自观察，再收齐合法选择，途中不公开其他席位当轮的新牌序。这是准备决策接口，不是完整八人结算引擎。

`yixian/tactical_search.py` 对每个候选使用同一组完整的对手假设，比较期望值与下尾风险。不会在不同隐藏局面分别挑最优牌序后合并成虚假的收益；无法解析或被截断的对战会阻断该候选，不删除不利样本后重新归一化。当前搜索只重排明确给定的1–8张牌；从更多手牌中选牌上阵仍需要经营动作的合法性接口。有限候选预算不是全空间最优解，也不是均衡策略证明。

`yixian/tactical_reference.py` 显式接入固定旧版yisim，使用参考卡牌ID及参考引擎指纹，不冒充当前客户端规则。当前示例收益是战后生命差代理值，不能等同于完整对局名次价值；所有参考搜索结果仍禁止作为当前版本训练标签。

## 回放对手与后续训练顺序

1. 当前先训练摆牌候选生成器：原1226训练局、150验证局，整局划分不变；不打开123个已使用的保留测试局。独立新实验600次更新，按验证NLL选模型。只训练排序复现，没有战斗奖励。
2. 先按版本核对记录生命差对应命元；再从开战输入模拟牌阵，比较胜者、最终生命差、行动回合数。每一阶段都需记录可执行内容和未知机制；终局相同不能唯一证明全部卡牌实现正确。
3. 校准通过后，采用回放经营状态、由通用摆牌模块重新决策的对手。优先筛选原局中存在同副职龙瑶的训练来源，再按当时已公开的核心牌比较。筛选只看截止轮前的信息，不能靠未来副职、成型牌或名次选对手。对方曾保留对策牌的概率可能更高，但不能保证针对当前策略。
4. 先验收单轮交互。改变牌序会改变伤害、命元与战后奖励，不能把回放下一轮的原状态覆盖到反事实对局。环境不能维护受影响资源时停止；不能据此宣称真实八人整局自我博弈。
5. 再训练龙瑶经营，使用同一数值/效果输入与候选路线战斗摘要。随后扩展具有完整规则覆盖的其他角色经营策略，使用共享模型与角色条件，当前策略和历史策略混合组成多门派八人桌。无须每个角色各训练独立大网络，也不能用八个相同龙瑶替代多角色环境。
6. 最后冻结新对手与种子，按对手角色/副职/版本分层验收。牌序复现、参考引擎表现、当前版本离线强度与实际游戏强度分别报告。

阶段晋级条件仍以`configs/training_stages.json`为准。S1历史验收保留，v3试训不是S2晋级。后续补齐规则和对手建模优先于重复训练相同配置。

2026-11-12用户进一步明确：经营路线先围绕每局存在的门派常规池、角色仙命和专属牌、首轮实际遇到的百家候选评估；其他条件来源按可得性和成本降低预期贡献。这是S3设计约束，不是固定数值折扣，也不表示角色奖励或目标卡一定可得。当前只整理供给来源与合法条件，暂不训练经营权重。常规池及赛季分离资料见`docs/REFERENCE_CATALOGUE.md`。
